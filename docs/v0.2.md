# v0.2 configuration and recovery

AGSV v0.2 keeps the v0.1 durable protocol while making runtime, session,
identity, profile, scheduling, and presentation choices explicit boundaries.
The default remains a Codex runtime launched through Herdr, so existing v0.1
configuration and zero-config repositories continue to work.

## Runtime, session, and caller boundaries

An actor profile selects a provider-neutral runtime adapter by `runtime` ID.
The adapter owns provider command construction, model and reasoning-effort
selection, initial-prompt delivery, resume arguments, capabilities, and
diagnostics. Adding an adapter does not add provider identifiers to
`agsv-core` or `agsv-protocol`.

`runtime.backend` selects the default session lifecycle backend. That backend
owns launch, checkpoint, resume, status, notification, stop, labels, and layout
operations. Each session row durably records both its lifecycle backend and
runtime. Reconciliation uses those persisted owners instead of silently
switching an existing actor when configuration changes. A legacy v0.1 session
without a runtime ID is interpreted as Codex and backfilled only after
validation succeeds.

Caller identity is a third, separate boundary. The Herdr identity adapter
derives an opaque binding from the calling pane and the store binds its hash to
one actor generation. A session handle is routing data, not authentication
proof. Debug-only fake identity is accepted only with the deterministic fake
backend and the explicit insecure-development opt-in.

Use `agsv --json doctor` to inspect runtime capabilities, lifecycle-backend and
caller-identity readiness, and enforcement levels. `agsv --json status` and
`agsv --json events` expose the effective durable context without leaking
opaque identity secrets.

## Actor and team profiles

Actor profiles contain a descriptive role, open capability IDs, runtime,
model, reasoning effort, and role instructions. Roles do not authorize
commands. `human_facing_primary` grants Primary operations and the single
Primary lease; `implementation_execution` grants implementation assignment and
execution operations. A profile may describe another role, such as research,
without either capability.

Team profiles select an actor profile and persist two pieces of team intent:

- `desired_instances` is reconciled by team creation, resume, and `agsv
  --json reconcile`. Zero disables persistent instances. A surplus actor with
  active work is retained until its work becomes terminal.
- `assignment_policy` is `first_healthy` or `least_wip`. Least-WIP counts
  durable nonterminal assignments and breaks ties by persisted actor order.

New configured actors and teams store immutable profile snapshots. Changing a
role or capability is therefore an identity-bearing change and requires a new
logical actor or team. Runtime/model/effort and role-file updates remain
launch configuration, but recovery still validates the durable session's
runtime owner.

Profile-less v0.1 state stays profile-less. The exact legacy `primary` and
`implementation` mappings are validated when explicit profiles are later
materialized; existing logical identities are not silently upgraded. For those
legacy teams, `team create --orchestrators` remains the compatibility instance
count and `first_healthy` remains the policy.

## Purpose, labels, and layout

`team create --purpose` and `team update --purpose` manage concise descriptive
team metadata. Purpose, generated session labels, tab labels, and pane
placement never participate in actor identity, authorization, leases, session
ownership, assignments, or fencing epochs.

The default capable-backend layout places the first Implementation beside the
Primary, then fills AGSV-managed tabs up to `max_panes_per_tab`. Sequence labels
choose the next available positive integer without renaming existing tabs.
`pane_label_template` may use `{session_label}`, `{team_purpose}`, and
`{active_request_title}`. A backend that lacks labels or layout capabilities
continues lifecycle work and reports those features as unsupported.

Herdr creation targets the workspace containing the authenticated Primary pane
rather than whichever workspace is focused. AGSV never moves a launched pane,
because moving it would change its opaque session handle.

## Compatibility and recovery

Tracked schema-version-1 configuration without profile tables is synthesized
into effective built-in profiles. Local legacy overrides keep their v0.1
meaning for that profile-less form and for built-in zero-config defaults. Once
explicit profile tables exist, their `runtime`, `model`, `reasoning_effort`,
and `role_file` values are authoritative; the parallel `[implementation]` and
`workspace.*_role` fields remain compatibility inputs rather than overrides.
A repository without tracked configuration uses embedded defaults and role
instructions, stores mutable state in the user state directory keyed by Git
common-directory identity, and does not create `.agent-supervisor/`.

The SQLite schema migrates in place. Protocol and domain JSON schemas continue
to be generated from Rust types; the v0.1 wire schema remains the compatibility
contract. Recovery is idempotent: durable operation IDs, actor and assignment
epochs, launch keys, per-record backend/runtime dispatch, and reconciliation
prevent duplicate launches and stale-generation results after interruption.

A rejected candidate remains the durable rework baseline even when a scoped
progress message moves the request from `changes_requested` back to
`in_progress`. The currently assigned, current-epoch actor may then complete
with a different immutable SHA. The rejected SHA stays forbidden, stale or
unassigned actors remain fenced, and retrying the same completion operation ID
returns the original result.

Run the following before relying on a customized configuration:

```text
agsv --json config validate
agsv --json doctor
agsv --json status
agsv --json reconcile
```

## Extending the registries

A new top-level runtime implements the `AgentRuntime` boundary in
`agsv-runtime` and is added to the compiled `RuntimeRegistry`. Keep its native
program, arguments, resume syntax, and launch-policy diagnostics inside the
adapter. Select the registered ID from an actor profile and verify it with
`config validate` and `doctor`.

A new lifecycle backend implements the `SessionBackend` contract in
`agsv-session` and the control-plane lifecycle behavior registered by
`SessionDriver`. It must validate that opaque handles belong to it and must
preserve launch idempotency/checkpoint semantics. Select its registered ID with
`runtime.backend`; old rows continue through the backend ID they persisted.

Adding an actor profile is configuration-only when its runtime already exists.
Give it a unique name, descriptive role, explicit capability set,
runtime/model/effort, and role file. A team profile then references that actor
profile and supplies desired count and assignment policy. Never add a provider
name to protocol role or capability types merely to make a new adapter work.
